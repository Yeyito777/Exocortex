# Audit: wire protocol and remote (SSH) efficiency — October 2026

Scope: daemon↔TUI IPC (`shared/src/protocol.ts`, `daemon/src/server.ts`,
`handler.ts` fan-out, `tui/src/client.ts`), the `exocortexd proxy` SSH
transport, bytes per event and per action, reconnect cost and round trips.
Images, conversation-open flicker, daemon CPU/DB, TUI render CPU and general
correctness belonged to other audits.

## Method

- **Live, read-only ledger.** A passive client on the live daemon socket
  (TUI capabilities, `list_conversations`, no subscriptions) recorded every
  event for 10 minutes; a second one subscribed only to this audit's own
  conversation for 6 minutes. Now `scripts/dev/wire-ledger.ts`.
- **Realistic SSH sessions.** A worktree daemon ran on a `VACUUM INTO` copy of
  the live database (3,408 conversations, including 1791667824123-k14mhj and
  the 34–64k-message OpenAI chats) with outbound network blocked. A scripted
  session used the real TUI `DaemonClient` (SSH probe adoption, history cache,
  reconnect path) through a fake `ssh` that runs the proxy behind a simulated
  link: one-way delay, rate cap, segment loss with head-of-line stalls, and
  SSH `-C`-style zlib stream compression for wire sizes. Now
  `scripts/dev/ssh-wan-sim.ts`. "Before" runs strip the new capabilities in
  flight, emulating an older TUI against the same daemon.
- "Raw" is JSON bytes (what each side serializes and parses); "wire" is
  compressed bytes as SSH `-C` would carry them.

## Findings, ranked by impact

### 1. `token_stats` pushed to every client after every turn — FIXED

The token statistics snapshot is **513 KB of JSON** on the live daemon (541
days of per-day, per-model buckets; 46–49 KB compressed). It was sent in every
bootstrap and broadcast to every client after every completed turn, title
generation, BTW turn and `llm_complete`. Only `/tokens` reads it.

- Live, passive client: **9 broadcasts in 10 minutes = 4.62 MB, 72% of all
  bytes received** (97% excluding the one-time sidebar bootstrap).
- Live, subscribed client: 3.08 of 3.30 MB (93%) in 6 minutes.
- Per turn completion: ~48.5 KB on the SSH wire and a 513 KB `JSON.parse` on
  the Mac, plus a ~78 ms head-of-line block on a 5 Mbit/s link. At the
  observed rate that is ~2.6 MB/h of wire and ~28 MB/h of JSON per TUI.

Fix (`token-stats-on-demand`): capable clients get no unprompted snapshots and
send `get_token_stats` when `/tokens` runs (one round trip). Older clients
still receive pushes, built once per broadcast and only if such a client is
connected. Against an older daemon the TUI falls back to the pushed snapshot
when `get_token_stats` is rejected. The daemon also stops building the
snapshot after every turn once no legacy client is connected.

### 2. Full sidebar broadcast on every native `exo` subagent spawn — FIXED

`exocortex-tool-runtime.ts` broadcast `conversation_moved` with the whole
sidebar to every client, ignoring capabilities: **1.68 MB raw / ~168 KB wire
per spawn**, and each made the TUI replace and re-sort all 3,400 rows. The
live database shows 24–44 subagent spawns per day this week (5–11 before):
4–7 MB/day of wire and 40–74 MB/day of JSON per TUI. Folder instruction edits
did the same.

Fix: the new row already arrives as `conversation_updated`; clients with
`sidebar-state-patch` now get only the affected folder rows as
`sidebar_state_patched` (a few hundred bytes). Older clients still get the
full snapshot.

### 3. Reconnect resends the whole sidebar — FIXED

Every `/ssh` reconnect (network drop, laptop wake, and every daemon restart
for a deploy) re-requested the bootstrap: the full 1.68 MB conversation list
(168 KB wire), plus `token_stats`, even when almost nothing had changed.

Fix (`sidebar-digest-sync`): the TUI keeps the remote sidebar as serialized
rows (`tui/src/sidebar-cache.ts`), follows sidebar events, and sends 256
bucket hashes (`shared/src/sidebar-digest.ts`) with the capabilities ahead of
the reconnect probe. The daemon answers that one bootstrap with only the rows
of buckets whose hash differs; the TUI rebuilds the full list before any
handler sees it. Reuse depends only on exact content hashes, so it needs no
revision log, survives daemon restarts, and self-corrects any drift in the
client's copy; an answer without its base falls back to a full list. Local
connections are unchanged.

Simulated SSH, copy of the live DB, scripted TUI client:

| Reconnect | Before (wire / raw) | After (wire / raw) |
| --- | ---: | ---: |
| Network drop, 5 rows renamed while offline | 220 KB / 2.21 MB | 8.0 KB / 51 KB (+2.8 KB digest up) |
| Daemon restart (deploy) | ~221 KB / 2.2 MB | 3.5 KB down + 3.9 KB up |

| 120 ms RTT, 5 Mbit/s, 1% segment loss | Before | After |
| --- | ---: | ---: |
| Probe pong → sidebar list | 700 ms | 88 ms |
| Reconnect → open conversation reloaded | 1,117 ms | 524 ms |

The rebuilt list was checked byte-for-byte against a fresh full list from
the daemon in every run.

### 4. The SSH bootstrap was always built for a capability-less client — FIXED

Over `/ssh` the probe's `ping` is adopted as the connection's bootstrap
request, but `client_capabilities` was written only after adoption, so the
daemon answered every SSH bootstrap as if to an old client. The probe now
writes the capabilities (and the sidebar digest) before the ping; the client
host is still attached only on adoption.

### 5. Multibyte characters corrupted at chunk boundaries — FIXED

The TUI decoded each socket/SSH read separately (`data.toString("utf-8")`), so
any multibyte character split across reads (emoji, accents, CJK, box drawing)
became U+FFFD. `JSON.parse` accepts those, so titles, messages and tool output
were silently corrupted — most likely in large payloads over `/ssh`, where
chunk boundaries fall anywhere. The SSH probe also handed over trailing bytes
pre-decoded. Both now use a streaming decoder / raw bytes; the daemon side
already did. (Other external clients of the socket were not audited.)

### 6. Redundant `usage_update` and `tools_available` broadcasts — FIXED

- `usage_update`: 130 of 149 live broadcasts in 10 minutes repeated the
  provider's previous value. Small in bytes (35 KB), but each woke every TUI.
- `tools_available` (~19 KB raw, ~2 KB wire) was re-broadcast on **every
  OpenAI response's headers**, i.e. once per model request in agentic OpenAI
  turns, though the registry almost never changes. (Not observed in the
  10-minute window, which had no OpenAI traffic; derived from code.)

Both now skip snapshots identical to the last broadcast. Bootstraps still
carry full values, and the Accounts screen is still told to refresh.

### 7. Opening a conversation costs two sequential round trips — NOT FIXED

`load_conversation` → `conversation_loaded`, then the TUI requests the
initial backfill. At 100 ms RTT: first page ~120 ms, backfill +~130 ms. The
first paint needs only the first; warm re-opens already shrink to ~0.4 KB via
the history cache. A daemon-pushed backfill would save one RTT per open, but
this path belongs to the open-flicker work. Suggested follow-up there.

### 8. Turn-end `history_updated` resends the buffered window — NOT FIXED

At the end of multi-round turns each subscriber receives the 15-turn window,
budgeted to 128 KB raw (~28 KB wire for k14mhj-like transcripts), most of
which the client already holds. The push cannot carry the client's cache
hashes. A follow-up could send only entries from the turn's first changed
index (a suffix patch), or let the daemon remember the entry hashes it last
sent per subscriber. Moderate value: only the viewed conversation, once per
turn.

### 9. Streaming events — no change needed

Live: 356 thinking chunks in 6 minutes averaging 96 B raw (most of it
envelope), a 5-second `streaming_started` heartbeat with the uncommitted tail
(≤4 KB here), and tool events. Repetition compresses well inside SSH's zlib
window, and only the viewed conversation streams to a client. Coalescing
deltas would mainly cut TUI wakeups (audit #2's area), not bandwidth.

### 10. No daemon-side write bound for stalled clients — NOT FIXED

`DaemonServer.sendTo` writes without checking `writableLength`. whale's
sshd uses the default `ClientAliveInterval 0`, so a Mac that vanishes without
closing TCP can leave its `exocortexd proxy` attached for hours (TCP
keepalive), with the daemon buffering every broadcast for it once the SSH
window fills. With findings 1, 2 and 6 fixed, the broadcast volume is small,
so this is now low-impact. Follow-ups: set `ClientAliveInterval` on whale, or
drop clients whose buffered output exceeds a cap (reconnect is now cheap).
`ss -x` showed no backed-up daemon sockets during the audit.

### Smaller notes

- Cold startup still downloads the full sidebar (168 KB wire). Persisting the
  sidebar cache per SSH host on disk would make startup incremental too.
- `queue_updated` sends the whole queued-message list on every change; it was
  empty live (39 B), but grows with queued subagent notifications.
- The live log shows ~1,000 socket connections an hour, mostly short-lived
  CLI/tool clients. Each receives broadcasts while connected; this is cheap
  now that `token_stats` is not broadcast.

## Compatibility

Every protocol change is capability-gated or ignorable:

| | Old daemon | New daemon |
| --- | --- | --- |
| Old TUI | unchanged | token stats pushed, full lists, full snapshots on spawn unless it declares `sidebar-state-patch` |
| New TUI | `/tokens` falls back to pushed stats; digest and probe preamble ignored (full list) | all fixes |

The daemon-only fixes (no identical `usage_update` / `tools_available`
repeats) apply to every client. Benefits that depend on the TUI (on-demand
token stats, sidebar resync, correct UTF-8 decoding) need the Mac TUI updated
too.

## Validation

- `bun run typecheck` clean.
- TUI: 1,708 pass. Shared (run from the repo root): 99 pass, 2 fail in
  `restart-impact.test.ts`, which fail identically on unmodified main.
  Daemon: 1,581 pass, 7 fail: the known sqlite clone-cursor pair and
  timing-sensitive bash tests (a different set fails on each run). Goals,
  unified-exec and async-loading pass when rerun on their own.
- New tests: token stats fan-out, request/reply and old-daemon fallback;
  split-UTF-8 delivery at every byte offset and across the probe handoff;
  probe preamble ordering; usage and `tools_available` dedupe; digest and
  delta semantics; sidebar cache rebuilds, base pinning and host isolation;
  subagent spawn patching. The UTF-8, subagent-spawn and `tools_available`
  tests were confirmed to fail without their fixes.
